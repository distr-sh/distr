As an end customer, you can create and manage secrets for your organization directly from the [Customer Portal](/docs/platform/customer-portal/). Secrets store sensitive configuration values such as API keys, passwords, and database credentials that your deployments can reference using template syntax.

## Managing secrets

Navigate to **Secrets** in the sidebar to view and manage your organization's secrets. The page shows each secret's key, template reference, creation date, and who last updated it.

### Creating a secret

1. Click **Create Secret**.
2. Enter a **Secret Key** (must start with a letter, can contain letters, numbers and underscores).
3. Enter the **Secret Value**.
4. Click **Submit**.

### Updating a secret

1. Click the secret you want to update.
2. Enter the new value (the key cannot be changed).
3. Click **Submit**.

If any active deployments reference this secret, the form lists the deployment targets that will be redeployed with the new value, and the button reads **Save and redeploy**.

### Deleting a secret

Click the delete button next to a secret and confirm by typing its key. A secret that a deployment still references cannot be deleted: the error names the deployment targets that use it, so you can remove the reference from their configuration first.

## Using secrets in deployments

Reference secrets in your deployment configuration using template syntax:

```
DATABASE_URL=postgresql://user:{{ .Secrets.DATABASE_PASSWORD }}@host:5432/db
API_KEY={{ .Secrets.API_KEY }}
```

The template reference for each secret is shown in the **Reference** column on the secrets page. Copy it directly into your deployment environment variables.

<Aside type="note">
  Secrets you create are scoped to your organization and are only available to
  your own deployments. Your vendor can manage the same secrets for you. Secret
  values are automatically redacted from deployment logs.
</Aside>

For the full template syntax reference and advanced usage, see [Secrets Management](/docs/controllers/secrets/).
