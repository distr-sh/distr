This guide walks you through how to use Artifact Entitlements to control which artifacts and tags your end-customers can access and pull from your Distr registry.

<Aside type="note">
  Artifact Entitlements are a Pro feature available in Pro, Enterprise, and Pro
  Trial plans. Learn more about [License
  Management](/docs/platform/license-management/) and [subscription
  plans](/docs/subscription-management/).
</Aside>

With Artifact Entitlements, you can control access to specific artifacts and their tags in your registry. You can grant access to all tags, specific tags, or future tags for one or multiple artifacts. Once you create your first artifact entitlement, customers will only see artifacts they have a valid entitlement for.

<Aside type="caution">
  Creating your first entitlement will restrict what all your customers see.
  After you create your first entitlement, your customers will only see
  artifacts which they have a valid entitlement for. Without any entitlement,
  your customers will see all artifacts and tags.
</Aside>

## Use case

Artifact Entitlements enable you to:

- **Control registry access**: Restrict which container images, Helm charts, and other artifacts customers can pull
- **Tag-based access control**: Grant access to specific tags (e.g., only stable releases) or all tags including future ones
- **Tiered artifact access**: Offer different artifact sets based on customer subscription tiers
- **Multi-artifact bundling**: Bundle multiple artifacts in a single entitlement for simpler management

## Entitlement features

1. Each entitlement can include one or multiple artifacts.
2. Each entitlement can grant access to specific tags, all tags, or all tags including future tags.
3. A customer can be associated with multiple entitlements.
4. Entitlement edits are reflected in the customer portal in real time.
5. Before creating your first entitlement, all customers can see all artifacts. After the first entitlement is created, customers only see entitled artifacts.
6. A [public artifact](/docs/registry/#public-artifacts) is exempt: every customer sees it and can pull it, with or without an entitlement.

## How to use it

If you don't see the feature yet, make sure you're on a Pro plan or Pro Trial. Once you're in, here's how it works:

1. **Create a customer:** If none exist, [create a customer](/docs/platform/customer-management/#creating-a-customer) first
2. **Navigate to Licenses** in the sidebar
3. **Click the customer** you want to create an entitlement for
4. **Select the Artifact Entitlements tab** and click **"Create Entitlement"**
5. **Give it a name** (required)
6. **Set an expiration date** (optional)
7. **Select an artifact** (required)
8. **Choose the tags**: grant **All tags**, or **Specific tags** with the tags you select and optionally an [auto-add tag regex](#auto-add-tag-regex) for future tags
9. **Save**: click "Save" and you're done

The customer can now access and pull the assigned artifacts and tags directly from your registry through their [customer portal](/docs/platform/customer-portal/).

## Choosing the granted tags

An entitlement grants either **All tags** of its artifact, which includes every tag you push later, or **Specific tags**. With specific tags, you have to select at least one tag, the customer only gets the tags you select and new tags are not added unless they match the [auto-add tag regex](#auto-add-tag-regex).

## Legacy view for multiple artifacts

An entitlement that bundles several artifacts opens in the legacy view. There you add artifacts with **"+ Add Artifact"** and choose for each one whether it grants all tags or only the tags you select. The legacy view does not support an auto-add tag regex.

## Auto-add tag regex

An entitlement with specific tags can grow with your releases. Enter a regular expression in **Auto-add Tag Regex** next to the tag picker, and every new tag of the artifact whose name matches it is added to the entitlement automatically. For example, `^2\.\d+\.\d+$` keeps a customer on every `2.x.y` release without you editing the entitlement after each push. The regex is only available for an entitlement with a single artifact.

### How matching works

- **When it runs:** The regex is checked whenever you push a tag that did not exist yet, or move a tag to a new manifest when [mutable tags](/docs/registry/#artifact-details) are enabled. Setting or changing the regex does not touch existing tags, so select those yourself. Tags synced from an upstream registry are not matched.
- **What is added:** The manifest the tag points to is added to the entitlement, just like selecting it in the tag picker. Every other tag pointing to the same manifest becomes available to the customer as well.
- **Syntax:** The regex uses [RE2 syntax](https://github.com/google/re2/wiki/Syntax) and may be up to 200 characters long. Lookaheads and backreferences are not supported. It must not start or end with whitespace; write `\s` or `[ ]` to match a space there.
- **Partial matches:** The regex matches anywhere in the tag name unless you anchor it with `^` and `$`. Matching is case-sensitive; prefix the regex with `(?i)` to ignore case.
- **At least one tag:** An entitlement with an auto-add regex needs at least one selected tag, since selecting all tags already includes future ones.

An auto-added tag is an ordinary entry of the entitlement. The customer can pull it right away, it is considered for update notifications and you can remove it like any tag you selected yourself.

### Examples

| Regex             | Adds                           | Does not add             |
| ----------------- | ------------------------------ | ------------------------ |
| `^2\.\d+\.\d+$`   | `2.0.0`, `2.14.3`              | `12.0.0`, `2.1.0-rc.1`   |
| `^2\.`            | `2.1.0`, `2.1.0-rc.1`          | `12.0.0`, `v2.1.0`       |
| `^\d+\.\d+\.\d+$` | `1.4.2`, `3.0.0`               | `1.5.0-beta.1`, `v1.4.2` |
| `-lts$`           | `3.2.0-lts`                    | `3.2.0`, `3.2.0-lts.1`   |
| `^[23]\.\d+\.\d+` | `2.1.0`, `3.0.4`, `3.0.4-rc1`  | `4.0.0`, `1.2.3`         |
| `(?i)^release-`   | `release-2026-10`, `RELEASE-7` | `pre-release-1`          |

## Managing existing entitlements

You can view and manage all artifact entitlements for a customer from their detail view in the Licenses section:

- **View entitlements**: See all entitlements with name, associated artifacts, and expiration
- **Edit entitlements**: Click an entitlement to modify its settings
- **Filter**: Use the search bar to filter by name or artifact

## Best practices

- **Start with broad access**: Consider starting with "All tags" for new customers, then refine as needed
- **Set expiration dates**: Use expiration dates for time-limited access or trial periods
- **Bundle related artifacts**: Group related artifacts in a single entitlement for easier management
- **Review regularly**: Periodically review entitlements to ensure they match your current access policies
