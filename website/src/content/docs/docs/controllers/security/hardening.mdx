---
title: Hardening
description: How to reduce what a Distr controller can access in the customer environment and what it sends to Distr.
slug: docs/controllers/security/hardening
sidebar:
  label: Hardening
  order: 8
---

- Run the controller in an environment dedicated to the deployments it manages: a host of its own for Docker, a cluster of its own for cluster scope and a namespace of its own for namespace scope.
- Disable log collection on the deployment target if the logs of its deployments must not leave the environment.
- Disable metrics on the deployment target. For Docker this also drops the mount of the host filesystem once the Compose file is applied again, for example by the next controller update.
- Create a Kubernetes deployment target with namespace scope when its charts need no cluster-scoped resources. The controller then has no access outside its namespace, and metrics are not available.
- Disable autoheal for all containers when creating a Docker deployment target, see [Autoheal](/docs/controllers/docker-controller/#autoheal).
- Create credentials that must not leave the environment there and reference them by name, see [External Secrets](/docs/controllers/security/external-secrets/).
- Pull the controller images from your own registry, see [Controller Image Repository](/docs/platform/branding/#controller-image-repository).
- Restrict who can read the credentials the controller keeps, root on a Docker host and the secrets of the controller's namespace in Kubernetes.
